# Sentinel（哨兵）产品需求文档

> Slogan：**你的密钥，寸步不让。** / _Your secrets, guarded._

- 版本：v0.2（已确认核心决策）
- 平台：macOS（Apple Silicon / Intel）
- 形态：桌面客户端（Tauri）
- 定位：**个人**、**零知识**、**可离线**、**可通过 GitHub 自同步**的本地密码管理器

---

## 1. 产品概述

Sentinel 是一款跑在 Mac 上的个人密码保险库。它解决一个具体痛点：**密码 / API Key 太多，记不住，又不放心交给云端商业密码管理器。**

三条产品红线，贯穿所有设计：

1. **绝对安全**：别人拿到你本地的加密文件、甚至拿到你同步到 GitHub 的文件，也**无法读取**任何一条明文，除非知道主密码。
2. **零知识同步**：同步走你自己的 GitHub 私有仓库，云端（GitHub）永远只看到**密文**。主密码和密钥永不落盘、永不上传。
3. **简洁**：只做「存、找、复制、同步」这一件事，不做浏览器插件、不做团队协作、不做密码分享，保持轻量。

### 1.1 目标用户

- 单人使用，多台 Mac 之间需要同步。
- 有 GitHub 账号，能接受用私有仓库做同步载体。
- 对隐私敏感，不信任 / 不想付费给商业密码云。

### 1.2 非目标（明确不做）

- ❌ 跨平台（Windows / Linux / iOS / Android）——首版只做 macOS。
- ❌ 浏览器自动填充插件——首版靠「一键复制 + 手动粘贴」。
- ❌ 多用户 / 团队共享 / 密码分享。
- ❌ 官方云同步服务——只用用户自己的 GitHub 仓库。
- ❌ 密码强度自动改写、暗网监控等增值功能（可列入远期）。

## 2. 核心功能

### 2.1 保险库解锁（Vault Unlock）

- 首次启动：创建主密码（Master Password），并展示**恢复提示**（可选填一句恢复提示语，明文存本地元数据，不加密——因为它只是给主人看的提示，不是密钥）。
- 后续启动：输入主密码解锁。
- 主密码**永不被存储**，只在内存中派生出密钥；应用锁定 / 退出后内存密钥立即清零。
- 支持自动锁定：闲置 N 分钟（默认 5，可配 1/5/15/30/从不）后自动回到锁定页。
- 支持 macOS 生物识别快捷解锁（Touch ID，作为**便利性**层，底层仍需先用主密码解锁过一次并缓存派生密钥到系统 Keychain——见 §3.5）。

### 2.2 条目存储（Items）

首版支持三类条目，覆盖用户明确需求（登录密码、API Key），并预留结构：

| 类型 | 字段 |
|------|------|
| **登录（Login）** | 标题、用户名、密码、网址、备注、TOTP（可选，双步验证码） |
| **密钥（API Key / Secret）** | 标题、Key 名称、值（Secret）、网址/服务、备注 |
| **安全笔记（Secure Note）** | 标题、正文、备注 |

通用字段（所有类型都有）：
- `id`（UUID）、`title`、`type`、`tags[]`、`favorite`（收藏置顶）、`createdAt`、`updatedAt`。
- 密码 / Secret 字段在界面上默认以 `••••••` 掩码显示，点眼睛图标才揭示。

### 2.3 查找与复制

- **全局搜索框**：按标题、用户名、网址、标签、备注实时过滤（内存中已解密，搜索是本地明文搜索，秒级）。
- **标签 / 收藏筛选**：左侧栏按收藏、全部、标签分组。
- **一键复制**：每条密码 / 用户名 / Key 旁有复制按钮，点击即写入剪贴板。
- **剪贴板自动清除**：复制敏感字段后，默认 **30 秒**自动从剪贴板清除（可配 15/30/60/从不），防止剪贴板被其他程序读取。
- **快捷键**（首版够用即可）：
  - `⌘K` / `⌘F`：聚焦搜索
  - `⌘N`：新建条目
  - `⌘C`：复制当前选中条目的主密码 / Key
  - `⌘L`：立即锁定
  - `Esc`：关闭弹层 / 返回

### 2.4 GitHub 同步

- 用户填入自己的 GitHub 仓库（推荐私有）+ 一个**细粒度 Personal Access Token**（只需该仓库的 `contents:read/write` 权限）。
- 同步内容：**加密后的保险库文件**（见 §3.3），不是明文。
- 同步方式：
  - **手动同步**按钮（首版默认，最可控）：拉取远端 → 合并 → 推送。
  - **自动同步**（可选开关）：解锁后拉取一次、每次改动后延迟推送、锁定前推送。
- **同步粒度（已定）**：首版用**整库单文件**（`vault.sentinel`）。实现简单、一次读写、Git 历史清晰；条目级合并逻辑全部放在应用层做，不依赖 `git merge`。
- **合并策略（三方合并，回答「两台电脑都改会不会冲突」）**：
  - 应用额外保存一份**上次同步成功的基线快照**（base）。同步时对每条条目做 base ↔ 本地(ours) ↔ 远端(theirs) 的三方比对：
    - 只有本地改了某条 → 采用本地；
    - 只有远端改了某条 → 采用远端；
    - 本地新增 / 远端新增不同条 → 两边都保留（**不冲突**）；
    - **两边都改了同一条且内容不同** → 真冲突，弹冲突框让用户选版本（另一版本存入历史）。
  - 结论：**在两台电脑改「不同」条目不会冲突**，自动合并；只有改了「同一条」才会提示。日常「解锁先拉取、改动勤推送」几乎遇不到冲突。
  - 每条条目带 `updatedAt` 作为时间参考；真冲突时默认预选较新版本，用户可改选。
- 同步流程：拉取远端密文 → 解密 → 三方合并 → （如有冲突则弹框）→ 重新加密 → 推送。整个过程云端只经手密文。
- Token 存储：Token 本身也是敏感信息，存入 **macOS Keychain**（系统级加密），不进 GitHub，也不进保险库明文。

### 2.5 设置

- 主密码修改（需旧密码验证 → 重新加密整个保险库）。
- 自动锁定时间、剪贴板清除时间。
- 外观：深色 / 浅色 / 跟随系统（首版主打深色科技风，浅色为次）。
- 同步配置与「立即同步」「同步历史/日志」。
- 导出 / 导入：
  - **导出加密备份**（`.sentinel` 文件，同样是密文，用于换机迁移）。
  - 首版**不提供明文导出**（安全红线）；如需迁移到别的工具，远期再评估加密码保护的 CSV。

## 3. 安全架构（核心）

> 设计原则：**Zero-Knowledge**。除了主密码在解锁瞬间存在于内存，任何持久化位置（本地磁盘、GitHub、Keychain）都**不含**可反推明文密码的信息。

### 3.1 密钥派生

- 主密码（用户输入）→ **Argon2id** KDF 派生出 256-bit 主密钥 `MK`。
  - 参数（首版，可调）：`m = 64 MiB`, `t = 3` 迭代, `p = 1` 并行度。
  - 每次创建保险库生成随机 16-byte `salt`，与参数一起存入文件头（明文，安全）。
- Argon2id 是当前抗 GPU / ASIC 暴力破解最强的密码哈希算法（优于 PBKDF2 / bcrypt），选它就是为了「即使文件泄露，离线爆破也极其昂贵」。

### 3.2 加密算法

- 保险库内容用 **XChaCha20-Poly1305**（AEAD，认证加密）加密。
  - 选它而非 AES-GCM 的原因：XChaCha20 的 192-bit nonce 极大降低了 nonce 复用风险，且在无 AES-NI 的机器上也快，实现更「难以用错」。
- 每条记录用独立随机 nonce；密文带 Poly1305 认证标签，任何篡改都会在解密时被检测并拒绝。

### 3.3 保险库文件结构

单个文件 `vault.sentinel`（本地）/ 同步到 GitHub 的同名密文文件：

```
┌─────────────────────────────────────────┐
│ Magic "SENTINEL1"  (8 bytes)             │  文件标识 + 版本
│ salt               (16 bytes)            │  Argon2id salt（明文）
│ kdf_params         (m, t, p)             │  派生参数（明文）
│ nonce              (24 bytes)            │  XChaCha20 nonce（明文，随机）
│ ciphertext + tag   (变长)                │  ← 整个 JSON 保险库加密后的内容
└─────────────────────────────────────────┘
```

解密后的明文是一个 JSON：
```jsonc
{
  "version": 1,
  "items": [
    {
      "id": "uuid",
      "type": "login",
      "title": "GitHub",
      "username": "me@example.com",
      "password": "明文密码",
      "url": "https://github.com",
      "totp": "otpauth://...",
      "tags": ["dev"],
      "favorite": true,
      "createdAt": 1710000000,
      "updatedAt": 1710000000
    }
    // ... api_key / note 类型
  ]
}
```
> 明文 JSON 只存在于内存中，从不写盘。写盘 / 上传前一定是密文。

### 3.4 内存安全

- 派生密钥 `MK`、解密后的明文 JSON 保存在 Rust 侧的**零化内存**（`zeroize` crate），锁定 / 退出时主动清零，降低内存转储风险。
- 前端（WebView）只通过 Tauri command 向 Rust 请求「当前解锁状态下的条目列表」，明文尽量短命；界面上密码字段默认掩码。

### 3.5 Touch ID（便利层，非安全依赖）

- 用户开启 Touch ID 后，`MK` 会被包装（wrap）后存入 macOS Keychain（受设备 Secure Enclave / 用户登录态保护）。
- Touch ID 只是「免每次输主密码」的便利；**安全边界仍是 Argon2id + 主密码强度**。文档明确告知：主密码弱，则一切防护弱。

### 3.6 威胁模型速览

| 攻击场景 | 是否防住 | 说明 |
|----------|:--:|------|
| 偷走本地 `vault.sentinel` 文件 | ✅ | 密文，需主密码 + Argon2id 爆破 |
| 拿到你 GitHub 仓库 | ✅ | 同上，云端只有密文 |
| 剪贴板被恶意程序读 | ✅（缓解） | 30s 自动清除 |
| 拿到你的 GitHub Token | ⚠️ | Token 只能读写那个仓库（拿到密文），且存在 Keychain 非明文 |
| 内存转储 / 冷启动攻击 | ⚠️（缓解） | zeroize 清零，但运行时内存必然有明文——所有本地密码管理器共有边界 |
| 主密码太弱 | ❌ | 用户责任，UI 给出强度提示引导设强密码 |

## 4. 技术架构

### 4.1 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 外壳 | **Tauri 2.x** | Rust 后端 + 系统 WebView，包体小（~10MB 级），内存占用低 |
| 前端 | **SolidJS + TypeScript** | 轻量、快、细粒度响应式；Vite 构建 |
| 样式 | 原生 CSS（CSS Variables）+ 少量工具类 | 不引重型 UI 库，保持简洁、可控科技感 |
| 加密 | Rust crates：`argon2`, `chacha20poly1305`, `rand`, `zeroize` | 全部为 audited 主流密码学库 |
| 序列化 | `serde` / `serde_json` | 保险库 JSON |
| GitHub 同步 | Rust `reqwest`（调 GitHub Contents API）或 `git2` | 首版走 REST API，免装 git |
| 系统凭据 | `keyring` crate（macOS Keychain） | 存 Token / Touch ID 包装密钥 |
| 本地存储 | 应用数据目录下单文件 `vault.sentinel` | `~/Library/Application Support/com.sentinel.app/` |

### 4.2 模块划分（Rust 后端）

```
src-tauri/
  src/
    crypto/        # Argon2id 派生 + XChaCha20 加解密 + zeroize
    vault/         # 保险库模型、条目 CRUD、内存态管理、锁定
    sync/          # GitHub Contents API 拉取/推送、条目级合并、冲突
    keychain/      # Token / Touch ID 包装密钥存取
    commands.rs    # 暴露给前端的 Tauri commands
    main.rs / lib.rs
```

### 4.3 前后端交互（Tauri commands 草案）

```ts
// 保险库生命周期
createVault(masterPassword) -> void
unlock(masterPassword) -> { items: Item[] }   // 返回解密后的条目（明文短命）
lock() -> void
isUnlocked() -> boolean
changeMasterPassword(oldPw, newPw) -> void

// 条目
listItems() -> Item[]
getItem(id) -> Item
createItem(item) -> Item
updateItem(id, patch) -> Item
deleteItem(id) -> void

// 剪贴板（带自动清除）
copySecret(value, clearAfterSec) -> void

// 同步
configureSync(repo, token) -> void
syncNow() -> { pulled, pushed, conflicts }
getSyncStatus() -> { lastSync, dirty }

// 设置
getSettings() / updateSettings(patch)
```

> 安全约定：`unlock` 之后，Rust 侧持有内存密钥；前端只拿「已解密条目」用于渲染，不接触 `MK`。锁定时 Rust 清零，前端清空 state。

### 4.4 数据流

```
主密码 ──Argon2id──▶ MK(内存)
                      │
             XChaCha20 解密
                      ▼
        vault.sentinel(密文) ──▶ 明文 JSON(内存) ──▶ 前端渲染(掩码)
                      ▲                                   │ 改动
                      └──────── 加密 ◀────────────────────┘
                                    │
                              手动/自动同步
                                    ▼
                        GitHub 私有仓库(仍是密文)
```

## 5. UI / 交互设计

### 5.1 设计语言

- **风格**：深色科技风为主，玻璃拟态（glassmorphism）+ 克制的霓虹强调色。
- **主色**：青蓝渐变（`#4FD1C5 → #3B82F6`），象征「冷静、可信、科技」。
- **背景**：近黑 `#0A0E14`，叠加极淡网格 / 光晕，营造纵深但不喧宾夺主。
- **字体**：无衬线（SF Pro / Inter），等宽字体用于密码 / Key 展示。
- **动效**：克制。解锁成功有一次「盾牌亮起」微动效；列表切换用淡入；不做花哨转场。
- **圆角 / 留白**：大圆角、充足留白，体现「高端、简洁」。

### 5.2 主要界面

1. **锁定 / 解锁页**：居中盾牌 Logo + 主密码输入框 + 解锁按钮；首次为「创建主密码」（两次输入 + 强度条）。
2. **主界面（三栏）**：
   - 左栏：Logo、收藏 / 全部 / 各类型 / 标签导航、底部同步状态 + 设置入口 + 锁定按钮。
   - 中栏：搜索框 + 条目列表（图标、标题、副标题、收藏星标）。
   - 右栏：选中条目详情（字段掩码显示、复制按钮、编辑 / 删除）。
3. **新建 / 编辑弹层**：类型选择 → 表单，字段旁即时复制。
4. **设置页**：安全、同步、外观、关于，分组卡片式。
5. **同步冲突提示**：模态，列出冲突条目，让用户选择保留版本。

> 详细视觉与交互见配套文件 `docs/ui-mockup.html`（可直接浏览器打开）。

## 7. 已定决策（v0.2 确认）

1. **同步粒度**：首版用「整库单文件」。两台电脑改不同条目由应用层三方合并自动处理，改同一条才弹冲突框（详见 §2.4）。
2. **TOTP 双步验证码**：纳入 **M2**（与主界面 / 条目 CRUD 同阶段）。
3. **导入 / 导出迁移**：首版**不做导入**；从 1Password / Chrome / CSV 导入放到 **M3 之后**。导出仅保留「加密备份」。
4. **签名 / 公证**：**个人使用**，首版自签即可，不做 Apple 公证（notarization）；日后若要分发给他人再评估。

> 里程碑已按以上决策同步调整（见 §6）。
